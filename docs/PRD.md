## 1. 一句话定义

**麦泡泡 PopMc 把麦当劳门店"此刻真实在售"的菜单，变成一盒可以拆的盲盒：你不知道吃什么的时候，拆一盒；拆完不只是知道吃什么，还得到一张能收藏的官方数据卡。**

它不是"随机数生成器"，而是**决策器官 + 收藏资产 + 可下单闭环**三合一。

### 2.2 竞争格局（据 2026-10-24 18:00 榜单快照）

- 头部（1000+ star）集中在**省钱 / 预算 / 派对策划 / 麦门认证**等"实用工具"与"身份认证"品类：`mcd-budget-meal`(1212)、`McLife-Desk`(1173)、`mcd-party-planner`(1165)。
- **抽盒/随机类已被占据但都在尾部**：`mcgacha`(58)、`mcd-gacha-collector`(49)、`McLottery-Alchemist`(59)、`meal-puzzle`(115)、`mcd-dex`(67)。
- 结论：**"随机推荐"本身不稀缺，"图鉴收集"也不稀缺。稀缺的是把随机结果变成可验证、可下单、可持续更新的资产体系。**

### 2.3 差异化定位（三条护城河，按可防守性排序）

1. **真实在售池**：每一次抽盒的候选池来自用户当前门店、当前时段的 `query-meals`。别的 gacha 是静态 JSON 池，抽出来门店可能没有；麦泡泡抽出来就能买。**这是只有接 MCP 才能做到的。**
2. **官方数据即卡面属性**：`list-nutrition-foods` 返回的能量/蛋白质/脂肪/碳水/钠/钙，直接定义卡的"攻击力/防御力"等属性。属性不是编的，是可核验的官方营养数据 → 收藏有价值感，且天然抵抗"胡编文案"的合规风险。
3. **赛季自动更新**：`query-meals` 的 tags 里有"上新""限时特惠"。把它们映射为"当期新卡"，官方上新即赛季更新，内容运营零成本、永不枯竭。

## 3. 用户与场景

### 3.1 目标用户

| Persona     | 画像                            | 核心诉求          | 占比预估 |
| ----------- | ----------------------------- | ------------- | ---- |
| **选择困难症小陈** | 22-30 岁上班族，工作日午餐前刷外卖 15 分钟选不出 | 帮我决定，且别踩雷     | 55%  |
| **收集控小林**   | 18-28 岁，买过泡泡玛特/谷子，喜欢"集齐"和晒图   | 有惊喜、有编号、能晒    | 25%  |
| **麦门信徒阿麦**  | 熟悉全菜单，知道巨无霸/板烧/麦辣             | 想被"懂"、想要仪式感和梗 | 20%  |

### 3.2 Jobs To Be Done

- 「当我不知道吃什么时，让我能在 30 秒内得到一个**我愿意接受**的答案。」（功能）
- 「当我每天重复点同一份餐时，让我有一点**开盲盒的期待**。」（情绪）
- 「当我吃到一样没试过的东西时，让我能**留下证据**并炫耀。」（社交）

### 3.3 场景剧本（P0 必须跑通的一条）

```
小陈 11:50 打开 WorkBuddy：「今天吃什么，随便，帮我抽一个」
  → 麦泡泡问：到店还是外送？（1 句，不啰嗦）
  → 定位到门店 1450713（华旭国际大厦）
  → 拉当前菜单 → 选出"工作日午餐"系列 → 洗牌
  → 拆盒：R 卡「龙焰鸡腿堡三件套」¥26.9
     盒面：系列色 + 官方商品图 + 编号 CH-07/14 + 稀有度 R
     文案：「韩式辣椒黄油风味。今日份的多巴胺。」
  → 一句话给结论：「就它了。¥26.9，比单点省 20.6。要下单吗？」
  → 用户：要 → calculate-price → create-order → 支付链接
  → 卡片入库：图鉴 CH 系列 8/14
```

**关键**：从"抽"到"付"必须一条链路走完。抽完不能下单的盲盒 = 玩具；能下单的盲盒 = 工具。这是评审和用户都能立刻感知的差别。

## 4. 需求拆解：为什么"随便抽一个"不够

用户的真实卡点不是"缺少随机数"，而是三个叠加的心理成本：

| 卡点        | 表现                        | 麦泡泡的解法                                |
| --------- | ------------------------- | ------------------------------------ |
| **决策疲劳**  | 选项太多（本店在售 130+ SKU），比较成本高 | 用"系列"把 130 个 SKU 折叠成 6 个心智桶，一次只在桶内随机 |
| **后悔厌恶**  | 怕抽到不喜欢的，浪费一顿饭             | 抽完可**免费换一抽**（1 次）；可设"忌口黑名单"永久排除      |
| **没有记忆点** | 吃完就忘，无情绪回报                | 卡片化 + 编号 + 图鉴 + 可分享图，把一顿饭变成一次"事件"    |

因此产品必须同时具备**收敛能力**（帮你选）和**回报能力**（让你爽）。只有前者是工具，只有后者是玩具。

## 5. 产品设计

### 5.1 双引擎模型

```
          ┌──────────────── 决策引擎 ────────────────┐
输入       │ 门店/时段 → 实时菜单 → 系列分桶 → 加权抽取 │ → 一个可下单的答案
场景       └──────────────────────────────────────────┘
          ┌──────────────── 收集引擎 ────────────────┐
          │ 稀有度 → 卡面 → 编号 → 图鉴 → 人格标签 → 分享 │ → 一次可留存的情绪
          └──────────────────────────────────────────┘
```

### 5.2 核心玩法（对照泡泡玛特，逐项做"食品化转译"）

| 泡泡玛特机制    | 麦泡泡转译                                          | 说明                              |
| --------- | --------------------------------------------- | ------------------------------- |
| 系列（一季一主题） | **菜单系列**：牛堡宇宙 / 脆鸡江湖 / 甜品星球 / 麦咖啡星系 / 随心搭子 / 分享派对 / 晨光早餐（时段限定） | 用官方菜单分类为骨架，中文命名重铸 |
| 常规款       | 门店常规在售单品                                      | `query-meals` 返回且无"上新/限时"标签     |
| 隐藏款       | 带 `上新` / `限时特惠` 标签的当期新品                       | 官方上新 = 自动进盲盒池，赛季自更新             |
| 超隐藏       | 系列内指定"图腾款"（如牛堡宇宙=巨无霸）                         | 人工白名单 pin，保证有"必追"目标             |
| 端盒（整盒买）   | **端盒 = 一餐**：主食 + 小食 + 饮料，去重且预算可控              | 抽 1 次得 1 件；"端一盒"得 3 件组成一餐，直接可下单 |
| 卡面 / 编号   | 程序化生成盒面 + 编号 `BU-01/12`                       | 编号来自池内序号，稳定可复现                  |
| 图鉴        | 收集册（本地 + 可导出）                                 | 按系列展示收集进度、未获得剪影                 |
| 抽盒机       | 「每日一抽」+ 免费换一抽                                 | 不做付费抽奖（合规红线）                    |
| 二级市场      | **不做**                                        | 明确不做交易/转赠，规避赌博与炒作风险             |

### 5.3 稀有度体系

| 等级  | 名称 | 判定规则（数据驱动，非人工逐个标注）                                         | 概率   |
| --- | -- | ---------------------------------------------------------- | ---- |
| N   | 常驻 | 默认                                                         | 70%  |
| R   | 人气 | tags 含 `爆款`/`人气`/`经典`，或 `originalPrice/currentPrice ≥ 1.4` | 22%  |
| SR  | 当期 | tags 含 `上新`                                                | 6.5% |
| SSR | 图腾 | 系列 `pinned` 白名单（每系列 1-2 个）                                 | 1.5% |

> 概率为**先抽等级、再在等级池内均匀抽**，因此每张卡的真实概率 = 等级权重 ÷ 该等级池容量，需在开箱页公示（见 §9）。  
> 保底：连续 10 抽无 R 及以上 → 下一抽强制 R+；连续 50 抽无 SSR → 强制 SSR。计数器持久化。

### 5.4 情绪价值设计（用户明确要求的核心）

情绪价值不能靠形容词，要靠**六个可被设计的时刻**：

1. **仪式时刻**：拆盒三段式文案 —— 洗牌（"正在摇匀本店 132 个可能"）→ 揭晓（"3…2…1"）→ 落卡。延迟 < 3 秒，不能真让用户等。
2. **惊喜时刻**：稀有度光效分级（N 无、R 银边、SR 金边流光、SSR 全屏粒子）。**低概率事件必须有视觉差**，否则惊喜不成立。
3. **收集时刻**：图鉴进度条 + 未获得剪影 + "还差 3 张集齐炸鸡江湖"。
4. **身份时刻**：**人格卡**——统计用户历史抽卡构成，输出"你是牛肉原教旨主义者 / 脆皮依赖症 / 甜品续命派"，附一行"你的麦门 DNA"。可截图分享。
5. **陪伴时刻**：每日一抽文案带当日元素（星期、天气占位、节气），"周三了，需要一点油炸的慰藉"。
6. **决策解脱时刻**：拆完必须给一句**结论句**，而不是丢一堆选项。"就它了"比"你可以选择以下 5 项"更有情绪价值。

> 反面清单（明确不做）：不做"再抽一次会更好"的诱导话术、不做充值/连抽折扣、不做"限时抽不到就没了"的稀缺胁迫。这些能提短期留存，但直接踩合规红线且伤害品牌。

### 5.5 忌口与健康兜底

- **黑名单**：用户说"不吃香菜/不吃牛肉/乳糖不耐"，解析为 tag/关键词排除规则，永久生效（本地存储）。
- **热量可见**：卡片背面展示 `energyKcal` 与官方"能量约等于"描述（MCP 已返回该字段，如"能量约猕猴桃2个"），开箱即有感知，不额外说教。
- **适量提示**：端盒若总热量超阈值（默认 1200 kcal），追加一句"这盒挺扎实，要不要加一杯无糖可乐？"——只提示，不阻止。

## 7. 合规设计（本项目最关键的一节）

盲盒机制在国内受《盲盒经营行为规范指引（试行）》约束，叠加赛事规则对"赌博/诱导消费"的明令禁止。麦泡泡采&#x53D6;**"盲盒是决策容器，不是销售形式"**&#x7684;立场，具体动作：

| 风险                      | 麦泡泡的做法                                                                                            |
| ----------------------- | ------------------------------------------------------------------------------------------------ |
| 被认定为"随机销售商品"（价格随机、货不对板） | **价格完全透明且确定**：抽中后展示该商品真实 `currentPrice`，用户付费金额 = 商品官方售价，不因稀有度浮动。稀有度只影响"卡面视觉"，不影响"你付多少钱/得到什么"     |
| 诱导过度消费                  | 无付费抽奖、无充值、无连抽折扣、无稀缺胁迫；"每日一抽"为软节流；不做二级交易                                                          |
| 概率不透明                   | 提供 `晒概率` 指令，输出等级权重与池容量，算得每卡真实概率                                                                  |
| 空盒                      | 池为空时**不抽**，直接提示并降级为常规推荐（FR-13）                                                                   |
| 面向未成年人                  | 不做任何"抽不到就亏"的表达；不做社交攀比排行                                                                          |
